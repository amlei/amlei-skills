# 播客大纲制作

把任意来源变成一档**能直接照着聊**的单人/对谈播客大纲。不是逐字稿，是分段口播大纲——每段列核心观点 / 关键素材 / 口述要点 / 小结过渡，录制时即兴展开。

**标准**：开头让听众知道"为什么要讲这个、为什么是现在"；正文让听众记住金句和转折；结尾让听众把内容接回自己的生活。

## 核心原则

- **第一人称对话感**——"我"对"你"讲，不是第三人称播报。想象听众是一个好奇但没读过这本书/没经历这件事的朋友。
- **分段口播大纲，非逐字稿**——逐字稿读出来生硬；大纲是给自己看的路标，录制时即兴展开，讲错重录该段、后期剪。
- **真诚 > 工整**——保留自然语气词，别剪太干净（会像机器人）。
- **每模块 = 观点 → 案例/素材 → 我的感受/经历 → 一句话小结**，每模块结束留呼吸点。
- **背景介绍语速快；核心观点和金句放慢、加重、前后留停顿。**

## 三种内容类型

### 拆书播客

来源是一本书。

1. **通读全书**——必须自己读完全文，不能只靠摘要。摘要丢细节、丢语感、丢语境。
2. **联网补充**——传主/作者近期访谈原话、主题相关的最新社会/行业数据、书中事件的后续发展。每条搜到原文核对。
3. **定主线**——不是"复述全书"，是从书中提炼一个与当下相关的讨论方向。
4. **按时间线或论点线推进**——传记类按人生时间线；知识类按论点递进。

### 灵感分享播客

来源是一个想法、一次经历、一篇笔记、一个观察。

1. **把灵感写清楚**——这个想法是什么？为什么此刻触动了我？
2. **联网找佐证/对照**——有没有数据、文章、别人的观点能支撑或反驳这个想法？
3. **定主线**——这期要传递的一个核心洞察是什么？
4. **按逻辑递进推进**——从"你有没有发现…"到"原来如此"到"所以我建议…"。

### 嘉宾对谈播客

来源是和一位嘉宾的对话。

1. **了解嘉宾**——背景、专长、近期动态、有故事可挖的经历。
2. **设计问题地图**——不是问题清单，是对话的"骨架方向"：从哪里切入、往哪里引、在哪里深挖、在哪里收。
3. **预设冲突点**——好的对谈需要观点碰撞。找到嘉宾可能和你/听众认知不同的地方，设计成讨论节点。
4. **大纲写成"方向+关键词"，不是逐题**——录制时对话会自然偏离，大纲是路标不是剧本。

## 工作流

### 第一步：明确来源和主线

- 内容来源是什么？（书 / 灵感 / 嘉宾）
- **"脊梁"**：这一期的核心讨论方向——一句话能说清
- **为什么是现在**——最近的一条新闻、一篇笔记、一个事件、一个感受，让"现在讲这个"变得必要

### 第二步：素材采集

按内容类型采集（见上方三种类型）。素材分两类：

- **硬素材**：书中原文金句（逐字照抄）、访谈原话（标出处）、数据（标来源+年份）、事件细节
- **软素材**：我的感受、我的经历、我的困惑——这些是让听众"代入"的入口

> 铁律：所有引用的原话、数据、产品版本号必须搜到原始出处核实。搜不到就不引，不编造。社交媒体转述不算原始出处。

### 第三步：写大纲

#### 大纲结构

```
# 播客口播大纲｜[标题]

> 格式说明 + 素材来源

## 节目定位（一句话）
## 标题（≤25 字，备选 3 个）
## Shownotes

## 开场钩子
## 模块 1～N
## 收尾
### 录制备注
```

#### 每个模块的五要素

| 要素 | 作用 |
|------|------|
| **核心观点** | 这段要传递的一句话 |
| **口述要点** | 关键场景/金句/关键词路标 |
| **小结/过渡句** | 段尾呼吸点，承上启下 |
| **播控提示** | 【停顿/配乐/语速/语气】|
| **呼应标记**（可选） | 标注与开篇主线/其他模块的呼应关系 |

#### 开场钩子

最个人、最抓人的部分。不是"播音腔"，是"跟朋友聊天"。推荐结构：
1. 一个触发事件（一篇笔记/一条新闻/一个感受/一个经历）
2. 我去查了 / 我想了一下——结果是有意思的 / 出乎意料的
3. 今天的现实（硬数据/正在发生的事，如果有的话）
4. 我的共鸣 + 为什么是现在
5. 主线问题 + 进入正题

#### 收尾

首尾呼应开场的主线。情绪弧：回扣 → 反转/讽刺 → 落点 → 开放问题。不要总结腔。

#### 呼应系统

开篇提出的主线问题，必须在正文和结尾有**至少 2-3 处呼应**。用 `【开篇主线回扣】` 或 `【社会冲击呼应】` 等标记，方便录制时识别。

#### Shownotes

- **一句话提要**
- **三个最该带走的点**
- **提及资料**：所有引用来源用超链接 `[名称](URL)` 分类列出
- **开放问题**（引流评论区）：1-2 个

## Gotchas

- **不要用子 agent 替代自己读全书**——摘要丢细节，必须自己读。
- **社交媒体转述 ≠ 原话**——用户看到的"XX 说"可能是博主的概括。必须追溯到原始访谈/演讲核实。
- **产品/模型版本号容易搞混**——必须从官网核实，不能凭印象。
- **就业/行业数据有时效性**——标注年份，优先搜最新。
- **JS 渲染页面**（产品官网等）普通抓取拿不到内容，需要 Chrome CDP 渲染。
- **嘉宾对谈大纲不能太死**——对话会自然偏离，大纲是方向不是剧本，写成关键词路标。

## 验证清单

定稿前逐项检查：

- [ ] 来源素材全部自己读过/核实过
- [ ] 所有金句/原话搜到了原始出处
- [ ] 所有数据有来源+年份
- [ ] 开篇主线在正文和结尾至少呼应 2-3 次
- [ ] Shownotes 提及资料用了超链接格式
- [ ] 每个模块有核心观点+口述要点+小结过渡+播控提示
- [ ] 开场钩子有"为什么是现在"
- [ ] 收尾首尾呼应，不用总结腔
- [ ] 嘉宾对谈类：大纲是方向不是逐题

## 输出规格

- **文件命名**：`<主题>播客口播大纲.md`
- **存放位置**：`自媒体/播客/<节目名>/`
- **长度**：不限，以完整为准
- **结构**：`#` 标题 → `##` 各段 → `###` 录制备注
